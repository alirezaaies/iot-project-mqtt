\section{هدف پروژه}
هدف نهایی، ساخت سامانه‌ای محلی برای دریافت داده از سخت‌افزار، نگه‌داری داده، نمایش گزارش و ارسال فرمان کنترل است. پروژه مرحله‌به‌مرحله ساخته می‌شود تا هر بخش پیش از اتصال به بخش بعدی به‌تنهایی قابل آزمایش باشد.

\section{قواعد توسعه}
\begin{itemize}
  \item فقط فایل و پوشه‌ای ساخته می‌شود که در مرحلهٔ جاری استفاده شود.
  \item هر مرحله باید ورودی، خروجی و آزمایش مستقل داشته باشد.
  \item اطلاعات محرمانه مانند رمز شبکه وارد
  \lr{Git}
  نمی‌شود.
  \item ابتدا راه اجرای مرحله نوشته می‌شود؛ سپس کد مطابق همان راه اجرا پیاده‌سازی و آزمایش می‌شود.
  \item قابلیت تازه فقط زمانی اضافه می‌شود که مرحلهٔ قبلی کار کند.
\end{itemize}

\section{وضعیت فعلی}
نسخهٔ کنونی فقط ارتباط زیر را پیاده‌سازی می‌کند:

\begin{LTR}
\begin{lstlisting}
ESP8266  --->  Wi-Fi  --->  Mosquitto MQTT broker
\end{lstlisting}
\end{LTR}

برد یک پیام وضعیت و دادهٔ آزمایشی منتشر می‌کند. مقدار داده هنوز از حسگر واقعی خوانده نمی‌شود و هیچ داده‌ای در پایگاه داده ذخیره نمی‌شود.

\section{مراحل پروژه}
\begin{enumerate}
  \item \textbf{مرحلهٔ جاری:} آزمایش کارگزار و انتشار دادهٔ آزمایشی از برد؛
  \item ذخیرهٔ پیام‌های دریافتی در
  \lr{SQLite}
  به‌عنوان یک ماژول مستقل؛
  \item خواندن و نمایش داده با یک برنامهٔ کوچک
  \lr{Python}
  ؛
  \item افزودن یک فرمان امن برای کنترل چراغ برد؛
  \item ساخت رابط وب ساده برای پایش و کنترل؛
  \item افزودن گزارش، آزمون‌های یکپارچه و تنظیمات امنیتی نهایی.
\end{enumerate}

فصل‌های مراحل آینده زمانی به سند افزوده می‌شوند که پیاده‌سازی آن‌ها آغاز شود. بنابراین عنوان خالی یا توضیح فرضی در سند نگه‌داری نمی‌شود.

\section{معیار پایان مرحلهٔ جاری}
مرحله زمانی کامل است که:

\begin{itemize}
  \item کارگزار بدون حضور برد پیام آزمایشی را دریافت کند؛
  \item
  \lr{firmware}
  بدون خطا ساخته و روی برد ارسال شود؛
  \item برد به شبکه و کارگزار وصل شود؛
  \item پیام وضعیت و داده در رایانه دیده شود؛
  \item پس از قطع و وصل موقت شبکه، ارتباط به‌صورت خودکار برگردد.
\end{itemize}
